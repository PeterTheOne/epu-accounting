## requirements
- python 3.14 (tested; the pinned dependency versions need at least 3.12)

## install
- poppler, see [pdf2image Installation](https://github.com/Belval/pdf2image#how-to-install)
- tkinter
 - linux: `[sudo] apt-get install python3-tk`
 - macOS: `brew install python-tk@3.14` (this upgrades Homebrew's `tcl-tk` to Tk 9, which breaks tkinter for older Homebrew Pythons built against Tk 8.6; upgrading their `python-tk@3.x` packages fixes them)
- Make sure the `de_DE` locale is available on your OS
- Python dependencies are installed into a virtual environment, see below

### virtual environment
Create the venv once (the `venv/` folder is ignored by git):

```
python3.14 -m venv venv
venv/bin/pip install --upgrade pip
```

If you have a `venv/` from the old Python 3.9 setup, delete it first (`rm -rf venv`); a venv can't be upgraded to a new Python version in place.

Then install the dependencies:

```
venv/bin/pip install -r requirements.txt
```

### running
Activate the venv in each new terminal session:

```
source venv/bin/activate
```

While it is active, `python` points to the venv's Python, so the commands below work as written, e.g. `python epu_accounting.py`. Run `deactivate` to leave the venv.

Without activating, call the venv's Python directly: `venv/bin/python epu_accounting.py`.

### testing
`tests/run_fixtures.py` runs the whole pipeline (clean, histograms/classification, database import, record matching, invoice PDF matching, numbering, export and the legacy CSV scripts) on the fixtures in `examples/`, answering the interactive prompts automatically. Run it before and after a change and compare the results:

```
venv/bin/python tests/run_fixtures.py examples/out/before
# ... make changes ...
venv/bin/python tests/run_fixtures.py examples/out/after
diff -r examples/out/before examples/out/after
```

Failing steps are listed at the end and written to `failures.txt` in the output folder. The invoice PDFs used for PDF matching are made-up examples generated by `tests/make_pdf_fixtures.py` into the output folder on each run. The GUI window of `match_pdf.py --gui` isn't opened by the tests; its page rendering is.

## bookamat workflow
- download your bank/credit card/PayPal statements as CSV files
  - for PayPal, go to Reports > Activity download > and choose Transaction type: Balance affecting
- create denylist with one column "contra_iban", listing your own IBANs
- `python apply_denylist.py [input_file] [denylist_file] [output_file] --preset [preset] --drop_empty --allowlist_text "rückzahlung,zinsen"` (presets: see `presets.py`)

## workflow
- remove your old *.db file!
- download your bank/credit card/PayPal statements as CSV files
  - for PayPal, go to Reports > Activity download > and choose Transaction type: Balance affecting
- create a folder named input with your CSV files.
- `python epu_accounting.py` and follow instructions.
- (optional) open SQlite database and remove unneeded transactions.
- (optional) create a folder named pdf with your invoices.
- (optional) `python match_pdf.py --gui [db_file] [pdf_directory]`
- `python number_db.py [db_file] [year]`
- create a folder named output.
- (optional) `python number_pdf.py [db_file] [output_directory]`
- `python db_to_csv.py [db_file] [output_file]`
- open output CSV, remove any columns you don't need.

## known issues
### match_pdf `locale.Error: unsupported locale setting`
The `de_DE` locale is not available on your OS.
- Check using `locale -a | grep de` or `locale -a` (Mac/Linux) which locales are installed.
- Add `de_DE` to your operating system or
- copy `.env.example` to `.env` and set `LOCALE` to a locale that is available on your OS
